Headless Claude runs go through the Claude Agent SDK instead of Ocean building `claude -p … --output-format stream-json` arguments and parsing their output. `claudeSdkOptions` maps the run onto SDK options: `resume`, `model` (unless provider-managed), `permissionMode: "plan"` plus `--restricted` for read-only, and `additionalDirectories` for the read grant. The SDK turns those into Claude Code's own flags and speaks its stream protocol. The SDK runs the user's installed `claude`, resolved past Ocean's shims; its bundled platform binaries (about 220 MB) are excluded at install. Ocean still spawns the process, so the session store gets its pid and its environment is the plan's. The process runs as its own process group: a timeout (`124`) or output budget (`125`) stops the whole tree, so a tool subprocess can't hold the run open, and a Ctrl+C or kill of Ocean is passed on to that group. The output budget counts raw stdout and stderr bytes as they arrive. A process ended by a signal is a failed run. Every SDK message is a `json` event. The SDK loads only when Claude runs. Claude's CLI argument builder is retired. A `ProviderAdapter` has either `build` (CLI arguments) or `run` (an SDK run); `runProvider` dispatches on it, and `buildProviderInvocation` refuses a provider that runs through its SDK. Adds `@anthropic-ai/claude-agent-sdk` 0.3.289 with its peers `@anthropic-ai/sdk` 0.131.0 and `@modelcontextprotocol/sdk` 1.32.0, pinned exactly.
