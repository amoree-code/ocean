# Design Thinking

Use before non-trivial implementation or open-ended work.

1. State the user outcome in one sentence.
2. Separate observed facts, constraints, assumptions, and unknowns.
3. Identify the smallest useful result and the people or systems it affects.
4. Compare viable approaches by correctness, risk, complexity, and reversibility.
5. Choose the smallest approach that meets the outcome.
6. Define the evidence that proves completion before execution.

Do not turn exploration into implementation without a clear outcome. Ask one focused question only when a missing choice materially changes the solution.
